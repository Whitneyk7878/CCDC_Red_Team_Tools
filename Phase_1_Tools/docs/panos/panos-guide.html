CCDC Red Team — PAN-OS 11.1.x

PAN-OS Training Scripts

Setup and usage guide for the dirty-state firewall scripts. Applies intentional misconfigurations for blue team hardening exercises, then cleans everything up afterward.

01 Prerequisites

On the Firewall

  • PAN-OS 11.1.x, standalone (not Panorama-managed)
  • A superuser admin account with XML API access enabled
    Device → Admin Roles → [role] → XML API — all checkboxes on
  • Management interface reachable on port 443 from your machine
  • A baseline config: at least 2 zones, a few security rules, URL filtering profile, anti-spyware profile, decryption policy, zone protection profiles

On Your Machine

  • Python 3.8+
  • pip install requests flask
    flask only needed for the Web UI
  • Network route to the firewall management IP on port 443
  • This repo cloned locally
Warning: These scripts commit live to the firewall immediately. Only run them against a training or lab device — never production.

State file: panos_exercise_state.json is written by Setup and read by Cleanup. It captures all original values so Cleanup can restore them exactly. Do not delete it between setup and cleanup.

03 Running the Scripts

Three ways to run — pick one. The Web UI is the easiest for instructors during a live exercise.

Best for live exercises. Runs in your browser, streams output in real time. No terminal needed once it's started.

Start the server

cd WORK_IN_PROGRESS_setupscripts
pip install flask requests
python3 CCDC_PANOS_WebUI.py

Open http://localhost:5000 in your browser.

Default PIN

The dashboard requires a PIN. Default is ccdc2024. Override with an environment variable before starting:

PANOS_UI_PIN=mypin python3 CCDC_PANOS_WebUI.py

Workflow

  1. Enter the PIN on the login screen.

  2. Enter the firewall's management IP. Choose username + password or paste an existing API key, then click Connect. A green status message confirms the connection.

  3. Click Apply Dirty State to push all misconfigurations and commit. Output streams live into the log panel. When complete, the exercise can begin.

  4. After the exercise, click Run Cleanup to reverse all changes and commit. The firewall is restored to its pre-exercise state.

Interactive terminal menu. Authenticates once, then lets you run setup or cleanup from a numbered menu.
cd WORK_IN_PROGRESS_setupscripts
python3 CCDC_PANOS_Run.py

  1. Enter the firewall management IP when prompted.

  2. Choose whether to use an existing API key or enter username + password. An API key is generated automatically from credentials.

  3. Select [1] Apply dirty state to start the exercise, or [2] Run cleanup to reset. Type yes at the confirmation prompt.

  4. Select [3] Exit when done.

Run setup or cleanup independently without the orchestrator. Useful for scripting or if you only need one half.

Setup only

cd WORK_IN_PROGRESS_setupscripts
python3 CCDC_PANOS_Setup_DirtyFirewall.py

Cleanup only

python3 CCDC_PANOS_Cleanup.py

Both scripts prompt for firewall IP and credentials (or an API key) at the start. Setup saves panos_exercise_state.json; Cleanup reads and deletes it.

Note: Cleanup requires the state file to exist. If it's missing it will refuse to run. Run Setup first, or use the orchestrator to manage both.

04 Authentication

All three methods support the same two auth paths:

Username + Password (generates API key automatically)

Enter your admin credentials when prompted. The scripts call the PAN-OS keygen API endpoint and exchange them for a session API key. The plaintext password is never stored.

Pre-generated API key

If your management auth profile blocks the keygen endpoint (e.g., RADIUS/LDAP with no local fallback), generate an API key manually first:

# From a browser — paste this URL and grab the <key> value:
https://<fw-ip>/api/?type=keygen&user=admin&password=<pass>

# Via curl:
curl -k "https://<fw-ip>/api/?type=keygen&user=admin&password=<pass>"

Paste the value from the <key>…</key> tag into the API key prompt.

TLS note: PAN-OS uses a self-signed certificate by default. The scripts pass verify=False and suppress the InsecureRequestWarning. This is expected in a lab context.

05 What Gets Applied

Setup applies 12 misconfigurations across four categories. All are reversed by Cleanup using the saved state file.

Misconfiguration Category Training Value
Logging disabled on all security rules Visibility Blue team is blind to traffic events in the firewall log
Syslog redirected to 172.31.40.6:514 Visibility Red team receives all firewall logs in real time
URL filtering set to allow-all on all rules Inspection C2, phishing, and data exfil URLs go unchecked
AV / IPS / anti-spyware profiles stripped from all rules Inspection No layer 7 security inspection on any traffic
DNS sinkholing disabled in all anti-spyware profiles Inspection Infected hosts can resolve and reach C2 via DNS
App-ID set to any on all security rules Inspection Rules are port-based only — application evasion is trivial
SSL/TLS decryption rules disabled Inspection All HTTPS traffic is opaque to inspection
Catch-all permit-any-traffic rule added (logging off) Network Any traffic from any zone is allowed through
Zone flood protection deleted from all zone profiles Network Firewall is vulnerable to SYN/UDP/ICMP flood attacks
Management plane permitted-ip list cleared Network Version fingerprinting and brute force from any IP
Rogue superuser netadmin created Persistence Persistent admin access even if passwords are rotated
Local auth bypass profile set as active mgmt auth Persistence Nullifies any RADIUS/LDAP requirement for admin logins

06 Cleanup

Cleanup reads panos_exercise_state.json and precisely reverses every change — restoring original values per rule, per profile, per object. It then commits and deletes the state file.

What gets restored

  • Original log-end / log-start per security rule
  • System syslog setting, per-rule log-setting; rogue syslog and log forwarding profiles deleted
  • Original URL filtering profile per rule; allow-all profile deleted
  • Security profile XML per rule (AV/IPS/spyware)
  • DNS sinkhole config per anti-spyware profile
  • Original application list per rule
  • Decryption rules re-enabled
  • Catch-all permit-any-traffic rule deleted
  • Zone flood protection config per zone profile
  • Management IP restriction list (skipped if it was unrestricted before setup)
  • netadmin account deleted
  • Original management auth profile restored; LocalBypass profile deleted
Partial runs: Each cleanup step is wrapped in a try/except and continues on failure. If an individual reversal fails (e.g., an object was already deleted manually), it logs a warning and moves on. The commit still runs at the end.

07 Troubleshooting

Cannot reach <fw-ip> — check IP and that management HTTPS is enabled
Verify port 443 is reachable: curl -k https://<fw-ip>/api/. Check Device → Setup → Interfaces → Management and confirm HTTPS is checked. If permitted-ip is set, add your machine's IP.
Auth failed / Auth failed: …
Confirm the account has superuser role and XML API access enabled. If the firewall uses RADIUS/LDAP, the keygen endpoint may be blocked — generate an API key via the Web UI (Device → API Key Management) and paste it at the API key prompt instead.
No state file found — run the setup script first
Cleanup requires panos_exercise_state.json to exist alongside the scripts. If it was deleted, Cleanup cannot safely reverse changes. Re-stage the firewall, run Setup again, then run Cleanup.
Commit status shows error / pending
PAN-OS commits are queued and can take 30–60 seconds. If a commit is already running, the API returns a job ID rather than completing. Wait for it to finish in Device → Tasks, then re-run the script.
Skipped: [step description] printed during setup or cleanup
Each step is wrapped in a try/except. "Skipped" means the XPath wasn't found — usually the baseline config doesn't have that object (no decryption rules, no zone protection profiles, etc.). Safe to ignore unless the missing object is critical to the exercise.
Web UI shows "Connection lost" during a long setup
The PAN-OS commit step can take over a minute. The EventSource stream has a 120-second timeout. If it cuts out, the operation is still running on the server side — check the terminal where you started CCDC_PANOS_WebUI.py for the final output.

08 Customizing Object Names

All rogue object names and the syslog target are constants at the top of CCDC_PANOS_Setup_DirtyFirewall.py. Edit these before running if you need different values:

ROGUE_ADMIN          = "netadmin"
ROGUE_PASS           = "Winter2024!"
ROGUE_SYSLOG_PROFILE = "ExternalLogging"
ROGUE_LOG_FWD        = "ExternalLogging"
ROGUE_URL_PROFILE    = "allow-all"
ROGUE_RULE           = "permit-all-traffic"
ROGUE_AUTH_PROFILE   = "LocalBypass"
SYSLOG_IP            = "172.31.40.6"
SYSLOG_PORT          = "514"

The device and vsys targets are in General_Scripts/SetupScripts/panos/panos_lib.py:

DEVICE = "localhost.localdomain"   # default for a standalone PA
VSYS   = "vsys1"
